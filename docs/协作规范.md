# 协作规范（A / B / C 三人必读）

> 目标：**main 分支任何时候都能跑**；任何人随时能接手任何模块。

## 1. 分支规范

| 谁 | 前缀 | 例子 |
|---|---|---|
| A | `a/` | `a/day03-audio-loop` |
| B | `b/` | `b/day05-fsm` |
| C | `c/` | `c/day02-db` |

格式：`<前缀>/dayNN-<主题>`，**每天一条新分支**。
> ⚠️ 原指南写的 `git checkout -b day02-env` 三个人同名会撞车，**统一加前缀**。

`main` 是唯一交付分支：
- **任何人不得直接 push 到 main**（C 在 Day1 首次推骨架是唯一例外）
- 所有改动走分支 → PR → C 审核 → 合并

## 2. 首次在你自己电脑上跑起来（每人一次）

代码仓库在 **Gitee（码云）**：`https://gitee.com/LiangMoxuan/voice-agent`

### 2.0 先配 SSH 密钥（推荐，避免每次输密码）

私有仓库拉取也要身份认证。配一次密钥，以后 `pull` / `push` 都不用再输密码。

```bash
# 1) 生成密钥（一路回车即可，已有就跳过）
ssh-keygen -t ed25519 -f ~/.ssh/gitee_ed25519 -N ""

# 2) 复制公钥全文
cat ~/.ssh/gitee_ed25519.pub
```

打开 `https://gitee.com/profile/sshkeys` → `添加公钥` → 标题随便填 → 粘贴刚才复制的全文 → 确定。

```bash
# 3) 让 git 连 gitee 时用这把钥匙
printf '\nHost gitee.com\n    HostName gitee.com\n    User git\n    IdentityFile ~/.ssh/gitee_ed25519\n    IdentitiesOnly yes\n' >> ~/.ssh/config

# 4) 验证：看到 "Hi 你的名字(@用户名)!" 就成了
ssh -T git@gitee.com
```

### 2.1 克隆并跑起来

```bash
git clone git@gitee.com:LiangMoxuan/voice-agent.git
cd voice-agent
python3.12 -m venv .venv          # Windows: py -3.12 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
cp .env.example .env               # 然后填入自己的 API Key
python -m server.db init           # 建表
uvicorn server.main:app --reload --port 8000
```

验证：`curl http://localhost:8000/health` → `{"status":"ok"}`

## 3. 每天开工（5 条，30 秒）

```bash
cd voice-agent
source .venv/bin/activate          # 看到 (.venv) 才算好
git checkout main
git pull                           # 拿别人昨天的代码
git checkout -b b/day05-fsm        # 换成你自己的前缀和主题
```

## 4. 每天收工（4 条）

```bash
# 先 Control+C 停掉 uvicorn
pytest -q                          # 绿了才提
git add -A
git commit -m "feat(agent): 状态机主循环"
git push -u origin b/day05-fsm
```

然后去 Gitee 网页：`Pull Requests` → `新建 Pull Request` → 填说明 → 提交 → 群里 @C 审核合并。

## 5. commit 前缀

| 前缀 | 用途 |
|---|---|
| `feat:` | 新功能 |
| `fix:` | 修 bug |
| `eval:` | 评测相关 |
| `docs:` | 文档 |

建议带模块：`feat(agent): 增加 WRITEBACK 分支`。

## 6. PR 说明必须写三行

```
改了什么：
怎么验证：
有没有动协议/表结构：有 / 没有
```

## 7. C 合并前的两条红线

```bash
uvicorn server.main:app --port 8000    # 必须能起来
pytest -q                              # 必须全绿
```

任何一条不过 → **不合并**，在 PR 下方写具体报错。

## 8. 目录归属（**别改别人的文件**）

| 路径 | 归属 | 别人可以 |
|---|---|---|
| `frontend/` | A | 只读 |
| `server/audio/` | A | 只读 |
| `server/agent/` | B（`guardrails.yaml` 由 C 复核） | 只读 |
| `server/tools/` | B | 只读 |
| `server/main.py`、`db.py`、`bus.py`、`logging_mw.py` | **C** | 需要改动请提 PR 并说明 |
| `eval/`、`docker/`、`docs/` | C | 只读（`docs/design/` 谁写谁的稿） |
| `tests/` | 各写各自模块的测试 | — |

**要加数据库表** → 找 C，不要自己改 `db.py`。
**要改消息字段** → 走 PR + 三人签字，不要偷偷加字段。

## 9. 每日站会 19:00（15 分钟，C 主持）

每人三句：**昨天完成什么 / 今天要做什么 / 卡在哪**。
卡点当场分派到人，第二天优先解决。

## 10. 禁区

1. 不提交 `.env`、不把 Key 发群里
2. 不在 `main` 上直接 commit
3. 不改别人模块的文件（要改先说话）
4. 不为让测试通过而写死答案、特判 `case_id`
5. 不用成品商业外呼机器人当核心
6. 不对真实号码外呼（一次也不行）
